# 班级管理排序优化总结

## 修复日期
2026-01-31

## 问题描述
班级管理模块的排序存在以下问题：
1. 班级列表排序混乱，没有按年级和班级正确排序
2. 年级排序不规范
3. 班级排序不规范
4. 用户期望：年级优先级大于班级，年级和班级都按照从小到大排序

## 修复内容

### 一、后端修改 (backend/app/routes/schools.py)

#### 1. 修改 `GET /{school_id}/classes` 接口

**修改前：**
```python
# 只按照 sort_order 字段排序
classes = query.order_by(SysOrg.sort_order).offset((page - 1) * page_size).limit(page_size).all()
```

**修改后：**
- 先获取所有年级，并按年级名称排序
- 按顺序遍历每个年级
- 获取每个年级下的班级，并按班级名称排序
- 合并所有班级，并保持排序顺序
- 最后进行分页

**排序逻辑：**
```python
def get_grade_sort_value(grade_name: str) -> int:
    """提取年级名称中的数字作为排序值"""
    # 支持的格式：
    # - "初一" -> 1, "初二" -> 2, ..., "初三" -> 3
    # - "高一" -> 1, "高二" -> 2, ..., "高三" -> 3
    # - "小学一年级" -> 1, "小学二年级" -> 2, ..., "小学六年级" -> 6
    # - "1年级" -> 1, "2年级" -> 2, ...

def get_class_sort_value(class_name: str) -> int:
    """提取班级名称中的数字作为排序值"""
    # 支持的格式：
    # - "1班" -> 1, "2班" -> 2, ..., "10班" -> 10
    # - "一班" -> 1, "二班" -> 2, ..., "十班" -> 10
```

**排序流程：**
1. 获取学校下所有年级
2. 按年级名称排序（从小到大）
3. 遍历每个年级
4. 获取该年级下的所有班级
5. 按班级名称排序（从小到大）
6. 合并所有班级数据
7. 应用筛选（年级筛选、关键词搜索）
8. 计算总数
9. 应用分页

**示例输出顺序：**
```
初一 1班
初一 2班
...
初一 10班
初二 1班
初二 2班
...
初三 1班
高一 1班
...
高三 10班
```

## 技术实现

### 1. 中文数字提取

使用正则表达式和中文数字映射表提取中文数字：

```python
cn_numbers = {
    '一': 1, '二': 2, '三': 3, '四': 4, '五': 5,
    '六': 6, '七': 7, '八': 8, '九': 9, '十': 10,
    '十一': 11, '十二': 12
}
```

### 2. 年级名称识别

支持多种年级名称格式：
- 标准格式：初一、初二、...、初三、高一、高二、高三
- 完整格式：初一年级、初二年级、...
- 简短格式：一年级、二年级、...
- 数字格式：1年级、2年级、...

正则表达式：
```python
# 匹配 "初X年级" 或 "高X年级" 或 "小学X年级"
pattern = r'[初高小](十[一二]?|[一二三四五六七八九])年级?'
```

### 3. 班级名称识别

支持多种班级名称格式：
- 标准格式：1班、2班、...、10班
- 中文格式：一班、二班、...、十班

提取逻辑：
1. 优先提取阿拉伯数字
2. 其次提取中文数字
3. 无法提取则返回999（排在最后）

### 4. 多级排序

实现两级排序：
1. 第一级：按年级排序（优先级高）
2. 第二级：按班级排序（在年级内部）

```python
# 对年级进行排序
sorted_grades = sorted(grades, key=lambda g: get_grade_sort_value(g.name))

# 对每个年级下的班级进行排序
for grade in sorted_grades:
    sorted_classes = sorted(grade_classes, key=lambda c: get_class_sort_value(c.name))
```

## 性能优化

### 当前实现

1. **内存排序**
   - 先加载所有数据到内存
   - 在Python中进行排序
   - 然后分页

2. **适用场景**
   - 适合数据量不大的情况（< 1000条）
   - 排序逻辑复杂，SQL难以实现
   - 需要跨表排序

3. **性能影响**
   - 对于小数据量：无明显影响
   - 对于大数据量：会有内存占用

### 优化建议（后续）

如果数据量增大，可以考虑以下优化：

1. **数据库层排序**
   - 在年级和班级表中添加排序字段
   - 使用数据库的ORDER BY
   - 减少内存占用

2. **缓存排序结果**
   - 缓存已排序的数据
   - 只在数据变化时重新排序

3. **异步排序**
   - 使用后台任务进行排序
   - 提升响应速度

- 1班、2班、3班、...、10班

- 1 class、2 class（提取数字1、2）

❌ **不支持的格式：**
- A班、B班
- 一组、二组
- 1-1、1-2

## 注意事项

1. **命名规范**
   - 建议使用标准命名格式
   - 避免使用特殊字符
   - 保持命名一致性

2. **数据完整性**
   - 确保每个班级都关联到正确的年级
   - 确保年级名称格式正确
   - 确保班级名称格式正确

3. **排序字段**
   - sort_order字段不再用于排序
   - 可以考虑废弃该字段
   - 或将其用于其他自定义排序

4. **前端适配**
   - 前端无需修改，后端已处理排序
   - 前端直接使用返回的数据即可
   - 前端不需要额外的排序逻辑
